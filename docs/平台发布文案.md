## 二、项目详情（Markdown）

````markdown
# 小创 — 四轮麦轮语音导航机器人

> 语音声控 · 多点导航语音播报 · 一键自动定位
> ESP32-S3 + RK3566 + ROS 2 Jazzy + Web 控制台，整车成本约 ¥752.9

## 一、背景

想做一台"能自己跑、还能听懂话"的小车：不是遥控车，而是能**自主建图、自主导航**，
并且用**语音**跟人交互——喊一声就能开，走到哪个点会主动告诉你。

市面上现成的 ROS 小车动辄三四千，我手头的件大多是二手：
一块 leap_ros_pro 控制板、一台退役的 Panther X2、一个二手激光雷达、一套别人转让的语音模块。
本项目就是把它们拼起来，并且把**从"能动"到"能稳定建图导航"之间那一堆坑**全部填平——
这部分经验比代码更值钱。

## 二、系统架构

```
              ┌──────────────── 上位机 Panther（黑豹）X2 (RK3566) ────────────────┐
              │  ROS 2 Jazzy                                                      │
              │  ┌─────────┐   ┌──────────┐   ┌───────────┐   ┌──────────────┐   │
  激光雷达 ───┼─>│ 扫描归一化│──>│ SLAM 建图 │──>│ 轻量导航   │──>│ Web 控制台    │   │
  STL-27L     │  │ 定长2100 │   │ slam_    │   │ A*+局部避障│   │ :5173 / :3000│   │
              │  └─────────┘   │ toolbox  │   └─────┬─────┘   └──────────────┘   │
  语音模块 ───┼──────────────┐ └──────────┘         │                            │
  CI1302      │              ▼                       ▼                            │
  USB 声卡 ───┼─> TTS 播报   │   ┌───────────────────────────────┐               │
              │              └──>│ cmd_vel_shaper 限幅+符号+死区补偿│               │
              │  ┌──────────┐   └───────────────┬───────────────┘               │
  IMU+编码器 ─┼─>│ EKF 融合 │                   │ /cmd_vel                       │

              └─────────────────────────────────┼────────────────────────────────┘
                                                │ WiFi  micro-ROS over UDP :8888
                                                ▼
              ┌──────────────── 主控 leap_ros_pro (ESP32-S3) ────────────────────┐
              │  运动学解算 → 四轮速度环 PID → AT8236 驱动 → MG370 电机           │

**分工原则**：

- **主控（ESP32-S3）**只做实时活：运动学、速度环、编码器、IMU、电池，跑 50 Hz；
- **上位机（RK3566）**做重活：雷达处理、SLAM、导航规划、Web 服务、语音合成；
- 两者通过 **micro-ROS over WiFi（UDP 8888）** 通信，主控侧就是一标准 ROS 节点。

## 四、软件方案

### 1. 上位机 ROS 2（核心是"五个适配节点"）

原厂固件和导航栈之间有一堆"对不上"的地方，靠五个小节点补齐，全部用 C++ 写（Python 版本烧到 43% CPU）：

| 节点 | 解决的问题 |
|---|---|
| `scan_normalizer.py` | 雷达每圈点数在 2135~2176 抖动、且有 7.8% NaN，直接喂 SLAM 会崩 |
| `ekf_input_adapter.cpp` | 陀螺零偏开机被污染、轮速比例差 2%、主控坐标轴与 ROS 相反 |
| `web_tf_aggregator.cpp` | 网页只收到动态 TF，缺静态变换导致激光整体偏 92° |
| `cmd_vel_shaper.py` | 限幅 + 坐标轴符号翻转 + 低速死区补偿 + 原地转改弧线 |
| `map_relay.py` | 导航模式下地图只发一次（latched），中继成 1 Hz 让网页收得到 |

### 2. 定位与导航

- **建图**：`slam_toolbox`（Karto），扫描固定 2100 点、量程收到 4.5 m；
- **定位**：相关匹配（coarse-to-fine），只依赖里程计 + 2D 激光 + 静态地图；
- **规划**：A* 全局 + 局部采样避障（不依赖 Nav2，资源占用低）；
- **自动定位**：把一帧激光在整张地图上做全局匹配，**7 秒**定位，得分 0.95~0.97。

### 3. Web 控制台

Vue 3 + Foxglove WebSocket，功能包括：

- 实时地图/激光/位姿/电池/路径可视化，图层可开关；
- 键盘控制（WASD + QE）、**手机虚拟摇杆**；
- 建图/导航任务启停、地图保存与切换；
- **一键自动定位**按钮；
- **多点导航**：依次双击点位入队，到点自动前进下一个；
- **到达播报**：每到一点播报"到达 N 号点"。

### 4. 语音交互

```
说「小创小创」→ 唤醒 → 说「前进」→ 串口帧 AA 55 00 01 FB
   → ROS 节点解析 → /cmd_vel_raw → 整形节点 → 主控 → 轮子转
```

- 唤醒与指令识别**完全离线**（CI1302 模块内置）；
- 播报走在线 TTS（edge-tts，中文自然音），断网自动回退离线 espeak-ng；
- 说"停止"立即停车。

## 五、遇到的坑（这部分是精华）

做这套东西真正的难度不在"写功能"，而在**让整套系统自洽**。下面是踩过的 26 个坑里最有代表性的 8 个：

### 坑 1：雷达装了 -92°，但装在了 roll 轴上

ROS 2 的 `static_transform_publisher` 位置参数顺序是 `x y z yaw pitch roll`，
原配置把 `-92°` 写在第 6 位（roll）。结果整帧扫描被压成 **0.38 m 宽的窄带**，
几乎是 1 维数据，SLAM 自然全是重影。

> 排查方法：把扫描点变换到 `base_link` 后统计 y 范围，正常应该是几米，当时只有 0.38 m。

### 坑 2：雷达每帧点数不固定，SLAM 直接 abort

```
LaserRangeScan contains 2169 range readings, expected 2168
Mapper FATAL ERROR - unable to get pointer in probability search!
```

karto 按第一帧点数分配缓冲区，而雷达每圈点数在 2135~2176 之间随机。
**修法**：加归一化节点，重采样成固定 2100 点。

### 坑 3：NaN 被当成有效读数

归一化后仍然崩，因为扫描里有 7.8% 的 NaN。
karto 判无效用的是 `reading <= 0 || reading > threshold`，**NaN 和任何数比较都是 false**，
于是 NaN 被当作有效值算栅格索引，越界崩溃。
**修法**：归一化时把非有限值替换成量程上限。

### 坑 4：EKF 把 IMU 全拒了，yaw 冻结

车实际转了 593°，EKF 的 yaw 却停在 -2° 半小时不动。
原因是 `robot_localization` 默认的马氏距离门限在状态协方差被污染后，
把之后的每一帧 IMU 都判为异常丢掉了。
**修法**：关掉门限（`rejection_threshold = 1e9`）+ 开 `dynamic_process_noise_covariance`。

### 坑 5：主控坐标轴与 ROS 相反

网页按 W 发 `vx=+0.55`（ROS 标准"前进"），车却**往后退**。
主控固件的 x/y/ω 约定与 ROS 整体相反，而编码器反馈也跟随同一套约定。
**修法**：指令在整形节点统一取反、反馈在适配器统一取反——**只在一层做，避免双重取反**。

### 坑 6：命令低于 0.4 m/s，轮子完全不转

导航参数 `max_vx` 只有 0.18，命令发出去了车一动不动。

| 命令 | 0.10 | 0.20 | 0.30 | 0.40 |
|---|---|---|---|---|
| 轮速 | 0 | 0 | 0 | -58~-119 mm/s |

原因是速度环 PID **是纯 P**（`ki=0`）：轮子打滑时编码器读数接近目标值，
误差变小 → 输出变小 → 扭矩更不够，形成负反馈死锁。
**修法**：通过 ROS 服务在线改 PID 为 `kp=12, ki=1`（存在 NVS，不用烧录），
起步门槛从 0.40 降到 **0.20 m/s**，效率从 35% 提到 **65%**。

### 坑 7：导航在 1 米宽的走廊里必然糊

窄走廊沿轴向没有几何特征，2D 激光在"无特征方向"上是**数学退化**的：
前后挪 10 cm，扫描几乎完全一样。这个方向只能靠轮子，而麦轮会打滑。

这不是 bug，是物理限制。**缓解办法**：建图时沿走廊放几个纸箱当特征物，建完撤掉。

### 坑 8：雷达支架没固定，所有算法都白搭

车静止，用手轻轻掰一下雷达，网页上激光点相对墙体明显滑动。
`base_link → base_laser` 本该是恒定刚体变换，支架一松它就在随时间变化，
而 SLAM 仍按固定值计算 —— 等价于每帧都注入随机误差。

**容差**：距离 3 m 处，1° 误差 = 5.2 cm，正好一个栅格。所以晃动必须远小于 1°。
````

## 四、制作步骤

### 步骤 1：组装底盘与电机

把 4 个 MG370 减速电机装到底板上，装 80mm 麦轮。
注意**对角两个轮子的转向必须相反**（麦轮特性），接线后先手动测试正反转。

### 步骤 2：安装主控板与走线

leap_ros_pro 控制板固定在底板上层，四路电机线接到板子的电机接口，
编码器线接到编码器接口（注意 A/B 相不要接反，否则里程计反向）。

### 步骤 3：固定激光雷达

雷达装在车体中轴线上、尽量高一点（本项目 0.18 m），**必须用刚性支架 + 螺丝固定**，
不能用扎带或亚克力悬臂。装完用手晃车体，雷达应与车体完全同步。

> 这一步是整个项目最关键的一步。雷达晃动 > 1°，建图必然重影。

### 步骤 4：连接语音模块与声卡

语音模块（CI1302）和 USB 声卡都插到上位机的 USB 口（用拓展坞）。
两个模块都是 CH340 串口，**必须靠 USB 物理端口区分**，用 udev 规则绑定固定名字：

```udev
SUBSYSTEM=="tty", KERNELS=="1-1.2",   SYMLINK+="lidar", MODE="0666"
SUBSYSTEM=="tty", KERNELS=="1-1.4.1", SYMLINK+="voice", MODE="0666"
```

### 步骤 5：烧录主控固件

ESP-IDF 5.2.x 环境：

```bash
idf.py set-target esp32s3
idf.py build
python -m esptool --chip esp32s3 -p COM3 -b 460800 write_flash -fm dio -ff 80m \
  0x10000 build/leap_ros_max.bin
```

### 步骤 6：配置主控网络

浏览器打开 `http://<主控IP>/`（默认 192.168.31.117），设置：

- WiFi 账号密码
- 通信方式：`micro_ros`
- 底盘类型：`mecanum`
- **micro-ROS Agent 的 IP 和端口**（填上位机 IP，8888）

> 换网段后必须回来改 Agent IP，否则主控永远连不上。

### 步骤 7：部署上位机

```bash
# ROS 2 Jazzy + slam_toolbox + robot_localization + foxglove_bridge
cd host_ws && colcon build --symlink-install
cd web && npm install && npm run build
systemctl enable --now microros-agent chuyun-stack
```

访问 `http://<上位机IP>:5173/`。

### 步骤 8：标定（重要，决定建图质量）

1. **雷达外参**：把车正对 1 m 外的墙，看墙在雷达坐标里的角度，反推安装角（本项目 -92°）；
2. **轮速比例**：地面量 3 m 直线走一趟，对比里程计读数，得到比例系数（本项目 0.98）；
3. **速度 PID**：`ros2 service call /set_speed_pid ...` 试 `kp=12, ki=1`，
   看低速能否起步（本项目门槛从 0.4 降到 0.2 m/s）。

### 步骤 9：建图

网页点"开始建图"，以 **0.1~0.2 m/s** 慢速走一圈，转弯处放慢，结束后保存地图。

> 走廊、长直通道容易退化，可以在通道里临时放几个纸箱当特征物。

### 步骤 10：导航与语音

1. 点"开始导航" → 选地图 → 点"一键自动定位"（约 7 秒）；
2. 双击地图设目标，或开"多点导航"依次点几个点，车会依次前往并播报"到达 N 号点"；
3. 对车说「小创小创」→「前进」，验证语音控制。
